# 依 AIR 規則審查變更

`check` 只涵蓋能用 AST 判斷的規則（import、I/O、時間、亂數）；其餘規則靠這個審查。審查是**唯讀**的：不改檔、不 commit、不 push。發現的問題交回給改程式的一方處理。預設自己審；只有使用者要求，或這批待審的檔案多到一次看不完（十個以上）時，才交給沒參與實作的子 agent（Claude Code 的 subagent；Codex 明確呼叫 `$air-review`）：把 `review --bundle` 的輸出整段貼給它當輸入，不要讓它自己重跑 `review` 與 `git diff`（會把同樣的東西再讀一遍）。

## 步驟

1. `python3 AIR/air.py check` 先通過。它負責的規則（有〔hook 檢查〕標記）這裡不重複報，交回時會被拒絕。
2. `python3 AIR/air.py review --bundle`：相對 HEAD、含未 commit 的修改；審整個分支加 `--base main`。它依層列出要對照的規則與出處（`AIR/rules/<層>.md:行`，每層只列一次），底下是該層改到的 `.py` 與改到的行，最後是每個待審檔案的差異（新檔案整個列出加行號；搬移過來的檔案只附「搬自哪裡」、對舊路徑的差異與大綱，要全文加 `--full`）。上次審過、內容沒變的檔案只列名字（「沿用」），不必重審也不用再交。沒列出的檔案不審。
3. 讀差異，對每個檔案逐條對照列出的規則。搬移過來的檔案整個都在範圍：照大綱找要看的段落（例如 import 時就執行的敘述、對外的函式），只讀那幾行。規則帶著「只審程式抓不到的部分」時，就專看那個缺口。差異裡看不出的事（例如被呼叫的函式長什麼樣）才另外讀檔，只讀需要的那一段。
4. 什麼該報：
   - **這次變更引入的**。既有問題不報；行號要落在改到的行附近，否則會被拒絕。
   - **具體可修**，指得出檔案與行。「可能影響別處」要指出具體位置才算。
   - **有把握**：信心 0–1，不到 0.5 的不報；拿不準就不報，沒有就交 `findings: []`，不要硬湊。
   - 只依列出的規則判斷，不加規則以外的偏好。
5. 交回結果（格式如下；`review` 的輸出也附了精簡版）。遷移的批次結束時跟 `batch finish` 一起交（`python3 AIR/air.py batch finish --note "…" --review - <<'EOF'`），其他時候用 `review --result`。無效會被拒絕並列出原因，修正後再交；通過驗證才會記錄。
   ```sh
   python3 AIR/air.py review --result - <<'EOF'
   { ... }
   EOF
   ```
6. `priority` 0、1 的發現必須處理，或向使用者說明為什麼不處理。處理後只有改過的檔案要重審（`status` 會顯示幾個），其餘沿用；沿用檔案的發現仍然算數，`overall` 要把它們算進去。審查結果不能推翻 `check` 或 `verify` 的失敗。

## 結果格式

```json
{
  "findings": [
    {
      "rule": "FLOW-3",
      "title": "把篩選邏輯移到 steps",
      "body": "run() 第 12–15 行在迴圈裡依金額過濾訂單，這是計算；移到 steps 的 valid_orders，flow 只呼叫它。",
      "confidence": 0.8,
      "priority": 1,
      "path": "src/shop/flows/report.py",
      "lines": {"start": 12, "end": 15}
    }
  ],
  "overall": "fail",
  "explanation": "一個 FLOW-3 的問題；其餘對照過的規則都符合。"
}
```

- `priority`：0 ＝違反【必須】而且讓層的保證失效（step 接收工具物件、白名單外的第三方物件流出 adapters、為了讓測試通過改了預期結果）；1 ＝其他違反【必須】；2 ＝違反【建議】；3 ＝提醒。
- `overall`：有 priority 0 或 1 的發現就是 `fail`，否則 `pass`。
- 每個發現引用一條規則，`path` 用 `review` 列出的寫法。規則的出處由程式補上，不用自己數行號。
- 沿用的檔案不用再交；如果你真的重審了它（例如上次是誤判），加選用的 `"rereviewed": ["路徑"]`，它的發現就以這次交回的為準。
- 機器可讀的格式在這個資料夾的 `schema.json`（非互動模式、CI 可以用它規定輸出）。
